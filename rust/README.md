# libavif Rust Rewrite

This directory contains the Rust implementation of critical components of libavif, focusing on security improvements through memory safety.

## Project Goals

The primary goal of this incremental rewrite is to improve the security of libavif by replacing security-critical components with memory-safe Rust implementations. This approach allows us to:

1. Eliminate entire classes of memory-related vulnerabilities
2. Maintain compatibility with the existing C API
3. Incrementally improve the codebase without a complete rewrite
4. Leverage Rust's strong type system and ownership model

## Components Being Rewritten

The following components are being rewritten in Rust, in order of priority:

### 1. Memory Management Layer

A safe Rust-based memory management system that can be used throughout the codebase:

- Safe wrappers around buffer allocation and deallocation
- RAII-based resource management for all allocated resources
- Rust's ownership model to prevent use-after-free and double-free bugs

### 2. BMFF Parser

A memory-safe parser for the AVIF file format (ISO Base Media File Format):

- Strong typing to represent the box structure
- Pattern matching for safer parsing logic
- Automatic bounds checking through Rust's slice types
- Safe handling of untrusted input

### 3. Decoder Core

A safe Rust-based decoder implementation:

- Safe handling of untrusted input
- Robust error handling
- Memory-safe buffer management for decoded frames
- Safe FFI interfaces to existing codec implementations

### 4. Stream Handling

Safe alternatives to the current stream handling code:

- Rust alternatives to `avifROStream` and `avifRWStream`
- Use of Rust's `Read` and `Write` traits for safer I/O
- Leveraging Rust's slice types for automatic bounds checking
- Elimination of potential buffer overflows in stream operations

## Integration with C Codebase

The Rust components are integrated with the existing C codebase through:

1. FFI bindings generated by cbindgen
2. CMake integration for building and linking
3. Maintaining API compatibility with existing code

## Building

The Rust components are built as part of the normal CMake build process. The CMake configuration automatically:

1. Builds the Rust code using Cargo
2. Generates C headers using cbindgen
3. Links the resulting static library with the main libavif library

## Development Guidelines

When contributing to the Rust rewrite:

1. Maintain API compatibility with the existing C code
2. Write comprehensive tests for all new Rust code
3. Use Rust's type system to prevent memory safety issues
4. Document all public APIs
5. Use fuzzing to validate the security of parsing code

## Testing

All Rust components should be thoroughly tested:

1. Unit tests for individual components
2. Integration tests with the C codebase
3. Fuzzing tests for parsing code
4. Compatibility tests with existing test suite
